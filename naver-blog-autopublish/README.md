# 네이버 블로그 자동 발행 도구

## ⚠️ 경고 — 반드시 읽을 것

- **이 도구는 임시저장까지만 자동화하며, 실제 발행 기능은 코드에 아예 없다.**
  최종 발행은 항상 사람이 네이버 앱/웹에서 직접 버튼을 눌러야 한다.
- **이 도구는 본인 개인/사업 블로그 전용이다. 클라이언트 계정에는 절대 사용하지 않는다.**
- 네이버는 개인 블로그 "글쓰기 API"를 2020년에 어뷰징 방지 목적으로 공식 종료했다.
  이 도구는 Playwright로 실제 로그인 세션을 재사용해 브라우저를 조작하는 방식이며,
  이는 **네이버 이용약관을 우회하는 행위**다.
- **계정 정지 리스크는 전적으로 본인이 감수한다.** 네이버가 이런 자동화를 탐지해서
  계정을 제재할 가능성은 항상 존재한다.
- 로그인은 스크립트가 절대 자동으로 하지 않는다. `capture_session.py` 는 헤드풀
  브라우저를 열고, 아이디/비밀번호/캡차/2단계인증은 **사람이 직접** 입력해야 한다.
- 실행 중 캡차/재로그인 요구/2단계인증 화면/예상 밖의 URL을 감지하면
  스크립트는 **즉시 중단**하고 재시도하지 않는다.
- 하루 발행 개수는 하드 제한(기본 1개/일)되어 있다. `logs/publish_log.json` 으로
  이력을 추적하며 초과 시 발행을 거부한다.

## ‼️ SELECTORS는 실제 브라우저 개발자도구(F12)로 직접 확인해서 채워야 동작한다

`auto_publish.py` 상단의 `SELECTORS` 딕셔너리와 `WRITE_PAGE_URL_TEMPLATE` 의 값은
**전부 추측/자리표시용**이다. 네이버 블로그 에디터(SmartEditor ONE)의 실제 셀렉터는
자주 바뀌고 지금 실시간으로 확인할 수 없다. 반드시 직접 확인 후
`# TODO: 실제 셀렉터 확인 필요` 주석이 달린 값들을 채워넣어야 한다.

### 더 쉬운 방법 — `capture_selectors.py` (권장)

`capture_selectors.py` 는 사람이 클릭하는 요소의 셀렉터를 자동으로 계산해서
터미널에 출력해주는 **읽기 전용 진단 도구**다. 아무 것도 자동으로 입력/클릭/
제출하지 않는다 — 오직 사람의 클릭을 관찰해서 셀렉터 정보만 출력한다.

```bash
python capture_selectors.py <blog_id>
```

1. 저장된 로그인 세션(`session/naver_state.json`)으로 글쓰기 페이지가 자동으로 열린다
2. 터미널 안내에 따라 브라우저에서 순서대로 클릭한다: ① 제목 입력란 → ② 본문
   에디터 영역 → ③ 임시저장 버튼
3. 클릭할 때마다 터미널에 추정 셀렉터가 출력된다 — 그 값을 그대로
   `auto_publish.py` 의 `SELECTORS` 딕셔너리에 복사해 넣으면 된다
4. 끝나면 `Ctrl+C` 로 종료

### 수동으로 하고 싶다면

1. 본인 블로그의 글쓰기 페이지를 크롬에서 열고 F12(개발자도구) → Elements 탭
2. 제목 입력란, 본문 에디터(iframe 여부 포함), 임시저장 버튼을
   각각 클릭해서 정확한 클래스명/셀렉터를 확인
3. `auto_publish.py` 의 `SELECTORS` 딕셔너리와 `blog_id` 값을 실제 값으로 교체

셀렉터를 확인하지 않고 그대로 실행하면 요소를 찾지 못해 "이상 감지"로 분류되어
스크립트가 중단된다 (의도된 동작 — 추측값으로 잘못된 요소를 조작하는 것보다 안전).

## 설치

```bash
pip install -r requirements.txt
playwright install chromium
```

## 사용 순서

1. `.env.example` 을 `.env` 로 복사하고 `ANTHROPIC_API_KEY` 등 값 채우기
2. `python capture_session.py` — 최초 1회 실행, 브라우저에서 직접 로그인.
   세션이 만료되면(오래 사용 안 했거나 네이버가 강제 로그아웃 시킨 경우) 재실행.
3. `python capture_selectors.py <blog_id>` — **1회성 준비 단계.** `SELECTORS` 가
   아직 실제 값으로 채워지지 않았다면 실행해서 제목/본문/임시저장 버튼 셀렉터를
   확인하고 `auto_publish.py` 에 채워넣는다. 읽기 전용 진단 도구라 아무 것도
   자동 입력/클릭하지 않는다 — `SELECTORS` 가 이미 채워져 있다면 건너뛰어도 된다.
4. `python content_generate.py "역삼동 태권도장 여름방학 특강"` — 주제를 넣으면
   Claude가 제목+본문+이미지 프롬프트를 생성해서 `drafts/<타임스탬프>.json` 저장
5. `python auto_publish.py drafts/xxx.json` 로 임시저장까지 진행
6. 이후 네이버 앱/웹에서 직접 접속해 임시저장된 글을 확인하고, 문제 없으면
   사람이 직접 "발행" 버튼을 눌러 최종 발행한다 (코드가 대신 눌러주지 않는다)
7. 모바일에서 명령으로 트리거하고 싶다면 이 컴퓨터/홈서버에서
   `python telegram_bot.py` 를 상시 실행해두세요 (터미널 유지, 또는 systemd/tmux 등).
   이후 텔레그램 앱에서 `/포스팅 <주제>` 를 보내면 초안이 생성되고, 미리보기
   아래 '임시저장 진행' 버튼을 누르면 이 컴퓨터가 실제로 임시저장까지 진행합니다.

### ⚠️ `telegram_bot.py` 는 절대 클라우드에 배포하지 말 것

이 봇은 절대 Vercel 등 서버리스/클라우드에 배포하지 마세요. 매번 다른 IP에서
네이버 세션에 접근하면 "다른 기기/위치에서의 비정상 접근"으로 탐지되어
계정정지 위험이 커집니다. `session/naver_state.json` 을 만든 바로 그
컴퓨터에서 상시 실행해야 합니다.

본인만 명령을 보낼 수 있도록 `.env`의 `TELEGRAM_CHAT_ID`와 일치하지 않는
대화는 전부 무시합니다 (로그만 남기고 응답하지 않음).

## 파일 구성

| 파일 | 역할 |
|---|---|
| `capture_session.py` | 사람이 수동 로그인 → 세션 쿠키 저장 |
| `capture_selectors.py` | (읽기 전용) 클릭한 요소의 셀렉터를 계산해서 출력 — 1회성 진단 도구 |
| `content_generate.py` | Claude API로 블로그 콘텐츠 생성 |
| `auto_publish.py` | 저장된 세션으로 실제 임시저장 (발행은 하지 않음) |
| `rate_limiter.py` | 하루 발행 개수 제한 |
| `telegram_alert.py` | 텔레그램 알림 (선택, 없으면 콘솔 출력) |
| `telegram_bot.py` | 텔레그램 롱폴링 봇 — 모바일에서 /포스팅, /상태 명령으로 로컬 스크립트 실행 (선택사항) |

## 안전장치 요약

- 캡차/2단계인증 자동 우회 코드 없음 — 사람이 헤드풀 브라우저에서 직접 로그인
- 로그인 페이지 리다이렉트/보안문자 키워드 감지 시 즉시 중단, 재시도 없음
- 네이버 계정 비밀번호는 코드/`.env` 어디에도 저장하지 않음 (저장하는 건
  로그인 후 세션 쿠키 `session/naver_state.json` 뿐)
- 하루 발행 개수 하드 제한 (`MAX_POSTS_PER_DAY`, 기본 1)
- 타이핑은 문자 단위 랜덤 딜레이(30~120ms)로 사람처럼 입력
- 발행 버튼 클릭 자체가 코드에 없음 — 최종 발행은 항상 사람이 직접 한다
- 모든 시도(성공/실패/중단)는 `logs/attempts.log` 에 타임스탬프와 함께 기록
- 텔레그램 봇은 반드시 로컬/홈서버에서 상시 실행 — 클라우드 배포 금지 (IP 일관성 유지)
- 봇은 `.env`의 `TELEGRAM_CHAT_ID`로만 명령을 받음 (타인 접근 차단)
