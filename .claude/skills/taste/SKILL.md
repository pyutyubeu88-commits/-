# taste — 안목 검증 스킬

콘텐츠·디자인 산출물이 나올 때마다 "이거 진짜 나갈 만한가"를 판단하는 검증기다.
칭찬하러 쓰는 게 아니라 내보내기 전에 구멍을 찾으러 쓴다.

## 언제 쓰나
- 사용자가 "/taste", "안목 체크", "타스트 체크", "이거 어때", "이거 괜찮아?", "퀄리티 검토해줘" 라고 할 때
- 카드뉴스·랜딩페이지·컨설팅보고서·SNS 카피(인스타/블로그/쇼츠 대본 등)를 새로 만들거나 크게 수정한 직후 — 요청이 없어도 "안목 체크 해볼까?" 하고 먼저 물어본다

## 평가 기준 7가지

각 항목은 CLAUDE.md에 정의된 이 프로젝트의 브랜드 규칙에서 그대로 가져온 기준이다. 산출물 종류에 해당 안 되는 항목(예: 텍스트만 있는 카피에 "비주얼 규격")은 건너뛰고 이유를 한 줄로 밝힌다.

1. **후킹력** — 표지/첫 문장/제목이 3초 안에 눈길을 끄는가. 질문형·숫자형·손해회피형 등 후킹 장치가 있는가, 아니면 밋밋한 설명으로 시작하는가.
2. **정보 정확성** — 과장·허위·근거 없는 단정이 없는가. "무조건", "100%" 같은 표현을 남발하지 않는가.
3. **저장/공유 유도 CTA** — 마지막에 저장·공유·댓글·문의 등 행동을 유도하는 장치가 있는가, 아니면 그냥 끝나는가.
4. **톤앤매너 일치** — "친근하고 후킹 강한 반말체, 이모지 적당히"라는 이 프로젝트 톤과 맞는가. 너무 딱딱하거나(존댓말·설명체) 반대로 이모지 남발로 가벼워 보이지 않는가.
5. **타겟 적합성** — 강남구 소상공인/자영업자가 실제로 쓰는 언어와 공감할 예시인가, 아니면 일반론·번역투·업계 용어인가.
6. **비주얼 규격** — 카드뉴스는 1080×1350(4:5) 등 정해진 사이즈·포맷을 지켰는가. 해당 없으면 "해당없음"으로 표시.
7. **퍼스트프린서플 관점** — 불필요하게 복잡하거나 상투적인 표현·중간 단계가 없는가. 더 단순하고 강하게 줄일 여지가 있는가.

## 판단 원칙

- 근거 없이 점수만 매기지 않는다. "왜 중/하인지"는 반드시 원문에서 실제 문장·구간을 짚어서 말한다.
- 모호하면 관대하게 봐주지 말고 하로 매긴다. 이 스킬의 존재 이유는 통과시키는 게 아니라 걸러내는 것이다.
- 개선 제안은 추상적 조언("더 후킹있게 써라") 말고 바로 갖다 쓸 수 있는 대안 문장/구조로 준다.

## 출력 형식

아래 템플릿을 그대로 따른다. 설명 없이 바로 이 형식으로 출력한다. 톤은 반말체.

```
🔍 안목 체크

1. 후킹력: [상/중/하] — (한 줄 이유, 원문 인용 포함)
   → 개선: (구체적 대안)

2. 정보 정확성: [상/중/하] — (한 줄 이유)
   → 개선: (구체적 대안, 문제 없으면 생략)

3. 저장/공유 CTA: [상/중/하] — (한 줄 이유)
   → 개선: (구체적 대안)

4. 톤앤매너: [상/중/하] — (한 줄 이유)
   → 개선: (구체적 대안)

5. 타겟 적합성: [상/중/하] — (한 줄 이유)
   → 개선: (구체적 대안)

6. 비주얼 규격: [상/중/하/해당없음] — (한 줄 이유)

7. 퍼스트프린서플: [상/중/하] — (한 줄 이유)
   → 개선: (구체적 대안)

총평: (한 줄 — 바로 나가도 됨 / 한두 군데 손보면 됨 / 다시 써야 함)
```

설명이나 서론 없이 이 표부터 바로 시작한다. 길게 늘어놓지 말고 항목당 1~2줄로 끝낸다.
